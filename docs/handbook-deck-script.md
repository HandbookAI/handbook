# Handbook 分享讲稿（白话版）

> 配合 `docs/handbook-deck.html` 使用：投屏放幻灯片，你看这份稿子。
> 全程约 **10–12 分钟**。每页给了「讲的话」和「动作提示」。
> 楷体括号（像这样）是给你的提示，不用念出来。

---

## 开场（还没翻页时，10 秒）

大家好，今天占用大家十分钟，讲一个我最近在做的工具。先说结论：它解决的是"文档永远过期"这个老问题，而且顺便把 AI 改代码"改漏地方"的问题也解决了一半。往下看。

---

## 第 1 页 · 封面「每个仓库，自带一本活的手册」

（翻到封面，停两秒让大家看标题）

这个工具叫 Handbook。一句话：**给每个代码仓库配一本"活的"手册**。

"活的"是什么意思？两层：第一，它是从源码里**生成**出来的，不是人手写的；第二，代码变了它跟着变，**增量更新**，不用重写。

它同时服务两种读者：**人**，拿到一本能看懂的系统说明书；**AI agent**，拿到一张改代码用的地图。这两个后面都会演示。

（过渡）先说为什么要做这个东西。

---

## 第 2 页 · 痛点「我们每天都在为过期的文档买单」

（翻页，指着三张卡从上往下）

这页三个场景，大家应该都眼熟。

第一个，新人入职：架构图是两年前的，wiki 半年没更新，最后怎么办？拉着老同事**陪读三天代码**。老同事的三天也是钱。

第二个，写文档的人最委屈：文档写完那一天就开始过期，又没有任何机制把代码变更同步回来，慢慢地大家就默契地——**不看了**。

第三个是新问题，这两年才有的：让 AI 改代码。agent 改了 JSON 解析器，但这个项目还有个镜像的 XML 解析器，还有两处提示词模板里写死了格式——**它不知道，文本搜索也搜不全**，就漏改了。

（指底部虚线框）这三件事其实是同一个病根：**文档是手工拍的快照，代码是活物**。快照和活物之间的差距每天都在变大。

（过渡）那市面上没有工具吗？有，但都缺一环。

---

## 第 3 页 · 对比「不是没有工具，是没有闭环」

（翻页，别逐格念表，挑重点讲）

这页把常见方案摆在一起。重点看两列。

「让 LLM 一次性生成文档」——去年很流行。问题两个：模型凭印象写，**会编**；代码一变，只能整本重新生成，贵，而且每次生成的结构还不一样，没法对照。

「Agent 现场读代码」——这是现在大家的默认方案，Claude Code、Cursor 直接读。它读的确实是真代码，但**每接一个任务都从零探索一遍**：重复烧 token，上下文窗口也装不下整个大库，而且这次探索的结论，下次任务用不上，全浪费了。

（指金框列）Handbook 这列的差别：事实来自**静态分析**、逐条带行号可以验证；每个文件**保证**有卡片；代码变了 **resync 增量更新**；agent 直接能用。

（过渡）我知道大家心里在想什么——"那我直接用 Claude Code 不就行了？"下一页专门回答这个。

---

## 第 4 页 · 关键疑问「不是替代 Claude Code，是给它装外挂记忆」

（翻页，这页放慢，是全场最重要的一页）

先把立场说清楚：**Handbook 不是 Claude Code 的对手，是给它配的外挂记忆**。三个差别：

第一，**探索变沉淀**。agent 每次现场读库，读完就忘；Handbook 把整个库梳理一次，之后全队每个任务都复用这份结果。相当于把"每次现场问路"变成"发一张地图"。

第二，**对话变资产**。agent 在对话里得出的结论，随着对话结束就没了，也没法核对；手册的每个事实带行号，写错了谁都能指出来。

第三，也是我最喜欢的：**部落知识变清单**。"改这个 parser 必须跟着改那个镜像 parser"，这种事以前只存在老员工脑子里。手册里有个 Co-change 字段，专门记录"改 A 历史上总要跟着改 B"，agent 和新人都能查。

（过渡）那它整体是怎么转起来的？看下一页这张图。

---

## 第 5 页 · 闭环「生成 → 使用 → 回写」

（翻页，手沿着图从左往右走一遍）

从左往右：源码进来，先做**静态分析**——这一步不用大模型，纯解析，把整个库的函数、调用关系抽成一张调用图，这是"事实层"。

然后大模型上场，在事实之上分章节、写大白话叙述，生成两个产物：给人看的**手册站点**，给 agent 用的 **SKILL 地图**。agent 拿着地图做出**精确变更**。

（指红色虚线，加重语气）关键是这条红色的回路：代码改完，跑一条 resync 命令，手册**增量前滚**——只更新受影响的章节，不用重新生成整本。

有人会问：那这手册自己会不会过期？会——**如果没人跑 resync**。所以我们的做法是把它挂成 CI 任务，合并即更新。手册的新鲜度就从"靠自觉"变成了"靠流水线"。

（过渡）看看产物长什么样。先看给人的。

---

## 第 6 页 · 给人的那一半「像读书一样读代码库」

（翻页，指着仿真浏览器窗口）

这就是生成出来的手册站点，纯静态 HTML，双击就能打开，不用部署。

左边是章节目录，按系统的**执行顺序**排的——从启动、到解析、到主循环，像一本书的目录，不是按文件夹瞎排的。

（指正文）中间这段话，我特别说明一下：**这是模型真实生成的，一个字没改**。它把"语言适配器注册表"解释成"酒店前台各国翻译员的名册"——这是给新人看的文档该有的样子，不是给编译器看的。

（指函数卡片）往下每个函数带**行号**，这些行号和调用关系来自静态分析，模型无权改。所以叙述可以平庸，但**锚点不会说谎**——讲错了你顺着行号一查就知道。

（过渡）再看给 AI 的那一半。

---

## 第 7 页 · 给 AI 的那一半「agent 拿到的不是文档，是改码地图」

（翻页，左右两块分别讲）

左边是 SKILL 地图里一个章节的"定位块"：这章负责什么、入口概念是什么、碰哪些全局状态、还有刚才说的 Co-change——改这里历史上要跟着改哪里。agent 改代码之前先查这张图，就知道**影响范围**了。

右边是规划输出：agent 用手册定位以后，去读真实源码确认，最后输出的是**逐字精确**的编辑计划——旧代码块、新代码块、外加一份机器可读的变更声明。

这里有个安全设计值得一提：旧代码块是**逐字节匹配**的，如果实际代码对不上——比如别人先改过了——它**拒绝执行**，宁可失败也不改错地方。

（过渡）听到这大家可能会想：这里面这么多环节靠大模型，靠谱吗？下一页讲我们怎么防它。

---

## 第 8 页 · 为什么敢信「三道防线」

（翻页，三张卡从左到右）

第一道防线刚才说过了：**事实和叙述分层**。行号、调用关系这些硬事实来自静态分析，模型只写散文，碰不到事实层。解析不了的调用我们也不硬塞，单独隔离存档。

第二道有意思：章节结构不是模型一口气生成的，是**评审出来的**。内部有个"骨架医生"循环——一个角色提方案，三个角色（工程师、架构师、读者）并行挑毛病，机械校验通过才落地。（指小柱状图）这是真实记录：78 个文件里最初有 19 个不知道该归哪章，三轮评审全部归位。

第三道，**降级而不是崩溃**：任何一步模型抽风，都有确定性的备胎方案顶上；失败会被如实记进覆盖率报告，不会偷偷装作成功。

（过渡）这个工具本身的工程质量怎么样？

## 第 9 页 · 工程质量「不是 demo」

（翻页，快讲，别恋战）

几个数字：第一个最有说服力——**吃自己的狗粮**：它给自己这个仓库、78 个源文件，生成了 21 章全中文手册。（指引用块）下面这段系统总览就是它自己写的，没润色，大家可以感受一下文风。

另外：9 个包严格隔离，LLM 代码碰不到事实层；167 项测试全部离线跑，不要 API key；开发过程做了 3 轮对抗式评审，33 个问题全修了，评审记录在仓库里可以翻。

（过渡）大家最关心的：多少钱，怎么用？

## 第 10 页 · 成本与上手「三条命令」

（翻页，指终端块）

上手就三条命令：analyze 静态分析——**免费**，先看看识别效果；generate 生成——这步花 token；render 渲染成站点。代码变更之后 resync，只更新受影响的章节。

成本三个闸门：先用 brief 模式便宜地试水，满意再上 deep 精读；叙述有内容哈希缓存，重跑几乎不花钱；断点续跑不重复计费。实测参考：这个 78 文件的仓库，brief 全量大概**几十次模型调用**。

（指中间卡片，加重）安全这条重点说：源码**只发给 .env 里配置的那一个端点**。接内网 vLLM 或者网关，代码全程不出内网；工具本身没有任何遥测上报，代码可查。

（过渡）我知道大家在决定用不用之前还有几个问题，我提前答了。

## 第 11 页 · 三个必答题

（翻页，逐张卡念问题，答案说重点）

**代码发给谁？**——只发 .env 指定的唯一端点，内网部署就不出内网；演示和 CI 用内置 mock，零外发。

**手册自己会不会过期？**——会，如果 resync 没人跑。所以挂 CI，合并即更新。就算真断更了，SKILL 里的内容哈希还会把过期的页**标记出来**，它不会装新鲜。

**谁维护？**——（这里认领）我来负责，问题进群里 @ 我。补充一句：产物是纯静态文件，哪天不想用了，**随时停，不绑架任何仓库**。

（过渡）如果今天大家觉得可以试，落地就三步。

## 第 12 页 · 落地路线「三步走」

（翻页）

第一步，**试点一个仓库**：就挑新人问得最多、文档最烂的那个。生成中文手册发群里，大家帮忙挑错——事实带行号，好核对。

第二步，**接入变更流程**：PR 合并后跑 resync，手动或者 CI 都行。

第三步，**喂给 agent**：把 SKILL 地图挂到 Claude Code，改码前先过一遍 Co-change 清单。

（指下方虚线框，语气放诚恳）边界也说清楚，我们不装：叙述质量取决于接的模型，弱模型出弱散文——但事实层不受影响；目前深度支持五种语言，Java、C++ 要加 adapter，一门语言一个文件，一百多到五百来行，照着现成模式抄；首次全量生成是大头成本，大仓库先用 brief 试算规模。

# 附：现场答问小抄

**Q：叙述会不会一本正经地胡说八道？**
A：散文有可能平庸，但每个事实带行号，错了能立刻定位；而且章节结构经过三角色评审 + 机械校验，结构性胡说会被拦住。讲错的部分，resync 或者手工改卡片都能修。

**Q：大仓库（几千文件）能用吗？**
A：架构上就是为大库设计的——文件级卡片、批量并发、断点续跑。建议先 analyze（免费）看规模，再 brief 试算，deep 只给核心目录上。

**Q：跟 DeepWiki / 其他 AI 文档站有什么区别？**
A：两个本质差别——事实层是静态分析出来的、逐条可验证，不是模型通读硬写；有 resync 闭环，代码变更后增量更新，不是一次性生成完就死了。

**Q：为什么不直接用更长上下文的模型把整个库塞进去？**
A：塞得进去也留不下来——每次任务都要重新塞、重新烧钱，而且结论没有沉淀、没法团队复用。手册是一次梳理、全队复用、持续更新。

**Q：生成一次要多久？**
A：取决于仓库大小和端点速度。这个 78 文件的仓库，全流程十来分钟；纯静态分析秒级。

**Q：支持 Java / C++ 吗？**
A：还没有，加一门语言 = 写一个 adapter 文件（130–560 行，有五个现成模板照抄）。有需求的话排期做。

**Q：怎么防止它把敏感代码发出去？**
A：它只会请求 .env 里配置的那一个端点，没有别的出口；接内网端点就完全不出网。CI/演示用内置 mock，零外发。不放心可以抓包验证。
