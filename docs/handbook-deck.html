04 · 关键疑问

不是替代 Claude Code，是给它装外挂记忆

每次现场探索 → 一次沉淀复用

agent 每接一个任务都从零读库：重复烧 token，能读多少还受上下文窗口限制。Handbook 把整库梳理一次，全队、每个任务复用。

结论散在对话里 → 可核对的资产

现场探索的结论随对话即焚，事后无法核对。手册的每个事实带行号，讲错了任何人都能指出来、改回来。

文本搜索 → 联动记忆

「改 parser 必须跟着改镜像 parser」这种跨文件约定，grep 搜不出来。Co-change 字段把部落知识写成清单，agent 和新人都能查。

改码前查图，改完回写——Handbook 是 coding agent 的地图与记忆，不是它的对手。

05 · 工作方式

生成 → 使用 → 回写，一个闭环

左半边是「生成文档」，右半边才是价值所在：手册帮 agent 找全改动点，改完的代码又把手册滚到最新。它会不会也过期？会——如果 resync 没人跑。所以把它做成 CI 任务：合并即更新，新鲜度从「靠自觉」变成「靠流水线」。

07 · 给 AI 的那一半

agent 拿到的不是文档，是改码地图

SKILL 地图 · 每章一个定位块
# task-execution · 任务执行
Duty: 队列驱动的任务消费与执行
Entry concepts: queue / worker
State: reg-task-queue
Co-change: 改 parser 必查 镜像 parser + 模板
Core files: queue.py · worker.py

改动前先查地图：哪些章节在影响范围内、哪些全局状态会被波及、改 A 时历史上总要跟着改的 B。字段为空同样是结论：这一章没有需要担心的全局状态。

08 · 为什么敢信

三道防线，挡住大模型的不靠谱

01 · 事实与叙述分层

模型无权碰事实

行号、函数清单、调用关系全部来自 tree-sitter 静态分析；解析不了的调用隔离存档而不是混进图里。LLM 只负责在事实之上写大白话。散文可以平庸，锚点不会说谎。

02 · 结构靠评审出来

三个角色互相拆台

章节结构由「骨架医生」循环打磨：提案 → 工程师 / 架构师 / 读者三个评审并行审核 → 机械校验后才落地。评审输出损坏或格式非法时，一律按「不通过」处理——出错的评审员，不能成为放行的理由。

03 · 降级而不是崩溃

每一步都有备胎

读文件失败：整批 → 单文件 → 按函数分块，三级降级；叙述失败退回确定性文本；全部产物内容哈希缓存 + 断点续跑。一次模型抖动，毁不掉一次构建；失败会被记录在覆盖率报告里，不会虚报。

10 · 成本与上手

三条命令，出第一本手册

# .env 里放 OPENAI_API_KEY —— 官方 / vLLM / 内部网关，兼容即可
handbook analyze --source ~/code/myproj --work work/myproj # 静态分析，免费，先看识别结果
handbook generate --source ~/code/myproj --work work/myproj --narrate-lang zh
handbook render --work work/myproj --html --agent-site # 手册站点 + agent 地图
# 代码变更之后：
handbook resync --case case1 --work work/myproj # 只更新受影响章节，缓存命中不花钱
花多少

成本三闸门

brief 先试水再上 deep 精读；叙述按内容哈希缓存；--resume 断点续跑。实测锚点：本仓 78 文件 brief 全量约数十次模型调用；接内网端点时费用趋近于零。

代码去哪了

数据不出你的边界

源码只发往 .env 里配置的那一个端点——接内网 vLLM / 网关时代码全程不出内网，无遥测上报；CI 和演示走内置 mock，零外发、零 token。

什么仓库

大小通吃

大库自动分章（file 策略）；小而关键的库可手写章节骨架、逐函数精修（member 策略）。混合语言自动探测。

11 · 有问必答

决定采用之前，三个必答题

Q1 · 代码发给谁？

只发往 .env 指定的唯一端点。接内网 vLLM / 网关，代码全程不出内网；演示与 CI 走内置 mock，零外发。工具本身无遥测、无上报，代码可查。

Q2 · 手册自己会不会过期？

会——如果 resync 没人跑。所以把它挂成 CI 任务：合并即更新。手册新鲜度从「靠人品」变成「靠流水线」；万一断更，SKILL 里的内容哈希还会把过期页标记出来。

Q3 · 工具谁维护？

由 ______（分享人现场认领）负责，问题进 #handbook 群；167 项离线测试兜底。产物是纯静态文件，随时可停用，不绑架任何仓库。

12 · 落地路线

三步走，下周就能开始

试点一个仓库

挑一个新人常问、文档最烂的核心库。生成中文手册发到群里，收集「有没有讲错」的反馈——事实层有行号，很好核对。

接入变更流程

PR 合并后跑 resync（手动或 CI 任务）——新人和 agent 读到的永远是当前代码的手册，不是三个月前的。

喂给 agent

把 SKILL 地图挂到 Claude Code / 内部 agent。改码前先过一遍 Co-change 清单——「改 A 忘 B」从靠记忆，变成靠清单。

边界 · 我们不装
  • 叙述质量取决于所接的模型——弱模型出弱散文，但行号和调用关系等事实层不受影响
  • 目前深度解析五种语言（Python / TS / Go / Rust / Shell）；Java、C++ 等需新增 adapter（一门一个文件，130～560 行，照抄现成模式）
  • 首次全量生成是主要成本；deep 模式在大仓库上应先用 brief 试算规模
