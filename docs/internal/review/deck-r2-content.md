# Deck 内容评审 R2（仅内容：叙事 / 说服力 / 文案。不涉及视觉）

对象：`docs/handbook-deck.html`（11 页）。听众：决定是否采用该内部工具的中国工程团队。
结论先行：叙事骨架是好的（痛点 → 备选 → 闭环 → 两个产品面 → 可信 → 上手 → 落地），但**全片没有回答 2026 年听众必问的第一个问题——「我直接用 Claude Code 读代码就行了，为什么要多一个工具？」**；其次「手册自己会不会过期」「代码发到哪」「谁维护」三个决策者问题全部悬空。第 8 页是给自己人看的自嗨页。以下按严重度列出，每条附可直接粘贴的替换文案。

---

## HIGH

**1. [high][S3] 对比表缺了真正的竞品：让 agent 现场直接读代码（Claude Code / Cursor）。**
问题：表里只打「人肉 wiki」和「LLM 一次性生成」两个稻草人。2026 年在座每个人的默认方案是「让 Claude Code 自己去读」，这一列不出现，整页说服力归零，且听众会在心里替你补上并从此走神。
修复（最低限度：给表加第四列）：
- 表头：`Agent 现场读代码<br>(Claude Code / Cursor)`
- 事实锚定：`读的是真码，但每次从零探索`（mid）
- 覆盖保证：`上下文装不下整库，读到哪算哪`（no）
- 代码变更之后：`无沉淀，下次重新探索、重新烧 token`（no）
- AI agent 能直接用：`能用，但没有跨文件联动记忆`（mid）
- 质量控制：`结论散在对话里，无法核对复用`（no）
并在表下加一句定位收束：
`Handbook 不替代 Claude Code——它把 agent 每次现场摸索的结果，沉淀成一次构建、全队复用、改完回写的地图。`
更好的修复见第 19 条（专门一页）。

**2. [high][S1+S4] 「手册本身会不会过期」这个致命反问没有被正面回答，而且 S1 的措辞把半自动说成了全自动。**
问题：S2 刚控诉完「wiki 停更半年」，听众立刻会想「你这手册没人跑 resync 不也一样烂掉？」。S4 的「文档第一次有了自我更新的回路」是修辞不是回答——resync 需要有人/CI 去触发，「自我更新」经不起追问。
修复两处：
- S1 lede 中「——并在每次代码变更后增量更新，而不是重写」改为：
  `——代码变更后，一条 resync 命令增量更新，挂进 CI 即随合并自动跟进。`
- S4 尾句「文档第一次有了自我更新的回路。」改为：
  `它会不会也过期？会——如果 resync 没人跑。所以我们把它做成 CI 任务：合并即更新，手册的新鲜度从「靠自觉」变成「靠流水线」。`

**3. [high][S9] 安全问题零着墨：源码到底发给哪个端点？**
问题：这是内部采用评审的一票否决项。全片只有 S1 页脚一行灰字「任意 OpenAI 兼容端点」和 S9 一张「不挑端点」卡，都在讲灵活性，没人讲**数据边界**。
修复：S9「用什么模型 · 不挑端点」卡替换为：
`<span class="k">代码去哪了</span><h3>数据不出你的边界</h3><p>源码只发往 .env 里配置的那一个端点——接内网 vLLM / 网关时，<b>代码全程不出内网</b>；无第三方遥测上报。CI 和演示用内置 mock 端点，<b>零外发、零 token</b>。</p>`
（注意：「无遥测上报」上台前请对照代码核实一次，说错这句比不说更糟。）

**4. [high][S8] 整页是工程师自嗨，五个数字没有一个换算成听众利益。**
问题：「9 个包严格单向依赖」「167 个测试」「WASM 零编译」是给贡献者看的简历，不是给采用者看的理由。听众在这一页最容易走神。
修复：保留数字带形式，逐条改写口径（数字→为什么与你有关）：
- `9` → 说明改为：`LLM 代码与确定性代码按包硬隔离——模型抖动伤不到事实层`
- `167` → 说明改为：`项离线测试兜底：工具升级不心惊，坏了也是我们先知道`
- `3轮` → 说明改为：`轮对抗式评审，33 项问题全部修复并补回归——评审记录在 docs/internal/review/ 可查`
- `5` → 说明改为：`种语言开箱即用，安装零编译——clone 下来就能跑，不折腾环境`
- `78→21` → 保留，这是全页唯一对听众有感的数字，建议挪到第一位。

**5. [high][S10] 「谁来维护这个工具」没有答案，落地页有路线没有 owner。**
问题：内部工具的死法通常不是不好用，而是没人认领。决策者一定会问。
修复：在 S10 三步之后、limits 之前加一行（可用 lede 样式）：
`维护与支持：工具由 __________ 负责（分享人先认领），问题进 #handbook 群；产物是纯静态文件，任何仓库随时可停用——不绑架任何人。`

## MED

**6. [med][S3] 「一遍过」在中文里是褒义习语（一次通过），放在否定格里会被读反。**
原句：质量控制 → LLM 列 →`一遍过`。改为：`生成即定稿，无人复核`。

**7. [med][S10] 「跨文件联动改动的遗漏会显著减少」——「显著」无依据，是全片最容易被抓的一句空头支票。**
改为（从承诺效果退到承诺机制）：`改码前先过一遍 Co-change 清单——「改 A 忘 B」从靠记忆，变成靠清单。`

**8. [med][S9] 「五分钟出第一本」无依据，且与 S10「首次全量生成是主要成本」自相矛盾；全片没有任何一个真实成本数字。**
修复：标题改为 `三条命令，出第一本手册`；「花多少 · 成本三闸门」卡末尾追加一句真实锚点（上台前用 run-self 实测填空）：
`以本仓库实测：78 个文件 deep 全量 ≈ ____ tokens / ≈ ____ 元，resync 单章 ≈ 忽略不计。`
没有这个数字，「成本三闸门」三个字都是虚的。

**9. [med][S6] 「执行器可以闭眼替换」——听众下一句就是「代码要是已经变了呢？」，把最强的安全属性说成了鲁莽。**
原句：`执行器可以闭眼替换，resync 拿声明来更新手册。`
改为：`old 块逐字节匹配，对不上就拒绝执行——宁可失败，不改错地方；resync 再拿声明更新手册。`

**10. [med][S7] 「评审自己坏了？按拒绝处理——坏掉的评审员无权放行」是内部黑话，现场没人听得懂「坏了」指什么。**
改为：`评审输出损坏或格式非法时，一律按「不通过」处理——出错的评审员，不能成为放行的理由。`

**11. [med][S7] 收敛图 19→1→0 缺分母，「19」无从感知大小。**
原句：`↑ 真实记录：无家可归的文件数逐轮归零`
改为：`↑ 真实记录：78 个文件中，最初 19 个无家可归，三轮归零`

**12. [med][S8] 「3 轮独立 agent 对抗评审」会引发「AI 审 AI，能信吗」的反问，且「33 项缺陷」裸奔容易吓人。**
修复：见第 4 条的替换文案（关键是补上「评审记录可查」这个可验证性锚点，把质疑引向证据）。

**13. [med][S3/S9/S10] 「只为变化付钱」同一卖点原话级重复三次（S3「只付变化的钱」、S9「缓存命中的章节不花钱」、S10「只为变化的章节付费」）。**
修复：S3、S9 保留；S10 第二步改讲新价值：
`PR 合并后跑 resync（手动或 CI），手册跟着代码走——新人和 agent 永远读到的是当前代码的手册，不是三个月前的。`

**14. [med][S11] 「这是文档第一次成为基础设施」——「第一次」是站不住的大话（谁的第一次？）。**
改为：`文档从「欠下的债」，变成「随代码走的基础设施」。`（S4 的「第一次有了自我更新的回路」同理，已在第 2 条一并处理。）

## LOW

**15. [low][S3] 「缺失显式记账」——「记账」是实现黑话。**
改为：`每个文件必有卡片，缺一个都被显式标出，绝不静默跳过`。

**16. [low][S3] 「整本重新生成，贵且漂移」——「漂移」对非 LLM 工程听众含糊。**
改为：`整本重生成：贵，且每次结构都不一样，无法对照`。

**17. [low][S4/S9] 「增量前滚」是数据库黑话，全片出现 3 次。**
建议 S4 图注保留一次（配了解释），S9 注释「# 增量前滚，缓存命中的章节不花钱」改为 `# 只更新受影响章节，缓存命中不花钱`。

**18. [low][S6] 「空字段也是信息。」太禅，现场需要自己解释一遍等于没写。**
改为：`字段为空同样是结论：这一章没有需要担心的全局状态。`
同卡「哪些章节在射程内」可顺手改为 `哪些章节在影响范围内`（军事比喻可留可去）。

**19. [low][S7] 「也骗不出假覆盖率」——主语不明，谁骗谁？**
原句：`一次模型抖动，毁不掉一次构建，也骗不出假覆盖率。`
改为：`一次模型抖动，毁不掉一次构建；失败会被记账，不会虚报覆盖率。`

## 缺页建议（≤2，含整页文案草稿）

**20. [high][新增页，插在 S3 之后] 专页回答「跟 Claude Code 直接读，有什么不一样？」**（第 1 条的加列是保底方案，这一页是正解——这是全场最大的心理障碍，值得独占一页。）
草稿：
