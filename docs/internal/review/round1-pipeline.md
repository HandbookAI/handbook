1. **HIGH — `packages/skill/src/build.ts:45` + `:107-112` — flat-layout stage-page filter silently drops stage pages whose id doesn't match `^(stage|crosscut|side)-`.** [CONFIRMED, runtime]
   The renderer (`renderer/src/markdown.ts:177`) writes one `<sid>.md` per stage at the handbook root, and stage ids are whatever the LLM or the user authored (`normalizeSkeleton` keeps any non-empty id; member-strategy skeletons are hand-written). `buildSkill`'s flat branch keeps only files matching `STAGE_PAGE_RE`, so a stage id like `core-loop` produces a skill missing `references/stages/core-loop.md` while `references/index.md` still links it. `validateSkill` only checks that *existing* pages are linked, never that linked pages exist, so the loss is fully silent (verified: `nStagePages=1`, page absent, `validateSkill.ok === true`).
   *Fix:* derive the stage-page set from the ids actually linked in `index.md` (or from the skeleton via a `--work` option), or copy every root-level `.md` except the known set `{overview,index,register,registers,how_to_use,disambiguation}.md`; additionally make `validateSkill` error on index links whose target page is absent.

2. **HIGH — `packages/resync/src/resync.ts:189-197` — the delta baseline (`phase1/graph.json`) is destroyed before the downstream artifacts are updated; any crash/interrupt mid-resync causes permanent silent staleness.** [CONFIRMED, trace]
   Step 1 (`runPhase1`) overwrites `phase1/graph.json` in the work dir; the old graph exists only in memory (`before`). If the process dies or throws anywhere in steps 3-6 (Ctrl-C during the LLM card pass, disk error in `saveAssignment`, `loadOrganization` validation error, …), a re-run diffs the new graph against itself: `delta = {changed:[], added:[], deleted:[]}` (no `change.diff` to widen it). Cards are never regenerated, deleted files stay in `assignment.fileStage`/buckets and in organization pages, added files never enter the assignment at all — and the second run "succeeds" and writes a clean report. There is no recovery path short of a full pipeline re-run.
   *Fix:* write the fresh graph to a temp path (or snapshot the old graph, e.g. `phase1/graph.prev.json`) and only replace `phase1/graph.json` after step 6 completes — or persist the computed delta before mutating anything.

3. **MED — `packages/resync/src/resync.ts:220-231` (noLlm path) — per-function LLM prose is wiped from changed files' cards, contradicting the documented contract ("keeps old prose and marks it stale").** [CONFIRMED, runtime]
   `card.functions = inventory[file] ?? []` replaces the old `FunctionNote[]` with the bare structural inventory, whose `purpose`/`dataFlow`/`relations` are all `''` — even for functions that still exist unchanged. Verified: a deep card with function purpose `"PRECIOUS FUNCTION PROSE"` came out of a noLlm resync with `functions[*].purpose === ""` while only the card-level purpose kept (stale-marked) prose. Silent data loss in `phase2/cards/*.json`.
   *Fix:* merge old prose onto the fresh inventory: `card.functions = mergeFunctionNotes(inventory[file] ?? [], old.functions)` (qualname-keyed; `mergeFunctionNotes` already reads `dataFlow` via its `data_flow ?? dataFlow` fallback).

4. **MED — `packages/pipeline/src/cards.ts:246-255` + `:381-405` — with `onlyFiles`, previously *backfilled empty* cards outside the scope are counted as described, so `_coverage.json` claims full coverage that doesn't exist.** [CONFIRMED, runtime]
   The `onlyFiles` branch preloads every existing on-disk card (including `purpose: ""` backfills) into `cards`; the backfill loop then skips them (`if (cards[descriptor.file]) continue`), so they never re-enter `missing`. Verified: work dir with `_coverage.json = {missing:["a.py"]}` and an empty `a.py` card; after `generateCards({onlyFiles:['b.py']})` (the resync step-3 path) coverage became `{nDescribed:2, missing:[]}` while `a.py`'s card is still empty. The drift signal the file exists for is erased.
   *Fix:* count a file as missing when its card has an empty `purpose` (e.g. `if (cards[f.file]?.purpose) continue;` in the backfill loop), not merely when no card object exists.

5. **MED — `packages/resync/src/resync.ts:250-269` — `report.affectedStages` omits the former stage of deleted files.** [CONFIRMED, runtime]
   Deleted files are removed from `fileStage` (line 252) *before* affected stages are computed by scanning the new `assignment.fileStage` (lines 264-268), so `touched.has(file)` can never match a deleted file. Verified: deleting `alpha.py` (sole file of `stage-1`) yields `affectedStages === ["stage-2"]` — `stage-1` absent from the report consumed by callers of `resync-report.json` (the organization rebuild only survives via its independent `orderedFiles ⊄ bucket` dirty check).
   *Fix:* before deleting, record `oldAssignment.fileStage[file].stage` for each `delta.deleted` file and union those ids into `affectedStages`.

6. **MED — `packages/pipeline/src/narrate.ts:76-101` — `cachedCall` writes the deterministic *fallback* text into the content-hash cache on LLM failure, permanently pinning degraded prose.** [CONFIRMED, runtime]
   The `.then((text) => { …write(text)… })` runs after the `.catch` that substitutes the fallback, so a transient LLM outage caches `stage.description` under the same key a successful call would use. Verified: after one failing run, a second run with a healthy client made **zero** LLM calls and returned the fallback for both the stage summary and the system overview (the poisoned stage summary feeds the system prompt's hash, cascading the poison). Only a manual `--refresh` recovers; resync (which passes `cacheDir` and no `refresh`) inherits the degradation forever.
   *Fix:* track whether `produce()` succeeded and skip the cache write on the fallback path (or write fallback under a marker that is retried next run).

7. **MED — `packages/skill/src/build.ts:84-95` vs `packages/skill/src/validate.ts:67-69` — a handbook with zero registers builds a skill that can never pass validation.** [CONFIRMED, trace]
   The renderer writes `register.md` only when `model.registers.length > 0` (`renderer/src/markdown.ts:180-183`). `buildSkill` copies `registers.md` only if a candidate exists, and succeeds without it; `validateSkill` then unconditionally errors `references/registers.md is missing`, so `handbook skill` + `handbook validate` exits 2 for every register-less project (small codebases, `extractRegisters` returning `[]`).
   *Fix:* have `buildSkill` synthesize a stub `registers.md` ("no cross-stage registers identified") when no source page exists — or downgrade the validator check to a warning when the page is genuinely absent from the handbook.

8. **LOW — `packages/pipeline/src/cards.ts:256-262` — `resume` recomputes `todo` over *all* files, breaking the `onlyFiles` restriction.** [CONFIRMED, runtime]
   `todo = files.filter((f) => !cards[f.file])` (not `todo.filter`), so with `resume && onlyFiles` any out-of-scope file lacking a card is sent to the LLM. Verified: `onlyFiles:['b.py'], resume:true` with card-less `c.py` in the graph → LLM prompts contained `b.py` and `c.py`. Latent (no in-repo caller passes both today) but the exported option contract ("Restrict the pass to these files") is violated.
   *Fix:* `todo = todo.filter((f) => !cards[f.file]);`.

9. **LOW — `packages/resync/src/resync.ts:225-227` — the noLlm stale marker accumulates on every repeat change.** [CONFIRMED, trace]
   `purpose: old.purpose ? `${old.purpose} (stale: …)` : ''` appends unconditionally, so a file changed across N successive noLlm resyncs carries N copies of " (stale: code changed since narration)". (A same-case re-run doesn't retrigger it — the delta is empty — but a new change to an already-stale file does.)
   *Fix:* guard with `old.purpose.endsWith(STALE_SUFFIX) ? old.purpose : …`.

10. **LOW — `packages/planner/src/planner.ts:114-125` — action detection keys off the *first* parseable JSON block in the reply, so a final prose plan whose earliest ```json fence contains a `tool` key is misparsed as a tool call and the plan is discarded.** [PLAUSIBLE, trace]
    `extractJsonBlock` (core/util/json-extract.ts:12) returns the first parseable fenced block. If the model answers with the finished plan as prose (the supported `### EDIT` path) and an EDIT block's `new` content or an example legitimately contains `{"tool": "grep", …}` in a json fence (e.g. a change request about this very tool protocol), `typeof action.tool === 'string'` wins before the `### EDIT` prose check, a spurious grep runs, and the completed plan is lost into the transcript.
    *Fix:* only treat the reply as an action when the whole reply is a single action block (or check `response.text.includes('### EDIT')` *before* the action branch when `tool !== 'finish'`).
